# 프로필 — 프론트엔드 (화면·컴포넌트·스타일·문구)

vibe-dev가 고른다. 게이트가 아니라 일하는 방식이다 — 단계 생략 권한은 없다.

1. **읽기**: `docs/design-system.md`(토큰·컴포넌트 원천·하지 않을 것) → 바꿀 화면과 같은 패턴을 쓰는 화면 하나. 결정은 `grep "#<화면 ID>" DECISIONS.md`의 유효 줄.
2. **토큰 밖 값 금지**: 색·간격·글자 크기는 토큰으로. 없는 값이 필요하면 디자인시스템 변경은 별도 골 후보로.
3. **컴포넌트 재사용**: 비슷한 것이 있으면 쓴다. 새로 만들면 「계획 vs 실제」에 이유.
4. **권한·역할**: 역할별로 보이는 것이 다르면 완료 조건에 역할을 적고 QA도 역할마다.
5. **테스트**: 렌더·상호작용 테스트가 있는 레포면 완료 조건마다. 없으면(바닐라 프로토타입) 문법 검사 + 브라우저 QA가 검증이다.
6. **QA 신호**: 화면 파일은 `ui_globs` 밖이어도(헬퍼 `.ts`, i18n `.json`, 데이터 목업) 화면에 닿는다 — vibe-qa에서 브라우저로 본다.
7. **문구**: 용어 기준 문서가 있으면 따른다(예: 설계서 「화면 용어 기준」).
