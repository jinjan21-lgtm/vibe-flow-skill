# 프로필 — 백엔드 (API·서버 로직·데이터·배치)

vibe-dev가 고른다. 게이트가 아니라 일하는 방식이다 — 단계 생략 권한은 없다.

1. **읽기**: API 계약 문서·스키마·기존 엔드포인트 하나. 결정은 `grep "#<모듈·화면 ID>" DECISIONS.md`의 유효 줄(권한·금액·데이터 원천 결정이 자주 걸린다).
2. **계약 먼저**: 요청·응답 형식과 오류 코드를 테스트로 고정하고 구현. 기존 응답을 바꾸면 「영향·위험」에 호출하는 화면을 적는다 — 화면이 바뀌면 그 MR은 풀스택이다.
3. **데이터 변경**: 마이그레이션은 되돌리기 경로와 함께. 데이터 손상·유실 가능성은 리뷰 blocker 기준이다.
4. **권한**: 새 엔드포인트마다 권한 검사 테스트(허용·거부 각 1개 이상).
5. **QA 신호**: 화면에 닿지 않으면 vibe-qa에서 `브라우저: 해당 없음 — <이유>`(예: "배치 작업, 화면 호출 없음"). 응답 형식이 바뀌면 닿는다.
6. **설정·비밀**: 비밀 값은 코드에 넣지 않는다. 새 환경 변수는 「영향·위험」과 설정 문서에.
