# 프로필 — 풀스택 (화면 + API를 함께)

[frontend.md](frontend.md)와 [backend.md](backend.md)를 둘 다 따른다. 추가로:

1. **순서**: 계약(API 테스트) → 서버 → 화면. 화면이 가짜 응답에 기대지 않게, 계약 테스트가 통과한 뒤 화면을 붙인다.
2. **크기**: 풀스택 MR은 커지기 쉽다. 400줄·10파일 경고가 나오면 서버 MR과 화면 MR로 나누는 것을 「계획 vs 실제」에서 검토한다(같은 골, 두 MR — 선점 줄은 하나).
3. **QA**: 코드 테스트 + 브라우저 QA 둘 다. 서버 오류 응답이 화면에 어떻게 보이는지 시나리오에 넣는다.
